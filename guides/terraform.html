GUIDE 02

Terraform basics + GitHub Actions infra automation

Provision Azure infrastructure as code, keep state remote, and let a pipeline plan on every pull request and apply on merge.

Core workflow

terraform init       # download providers, configure backend
terraform fmt -check # formatting
terraform validate   # syntax and internal consistency
terraform plan -out=tfplan
terraform apply tfplan
terraform destroy    # tear down (careful)
ConceptMeaning
ProviderPlugin for a platform (azurerm, aws).
ResourceAn infrastructure object you create.
Variable / outputInputs and exported values.
StateTerraform's record of what exists. Must be shared and locked in teams.
ModuleReusable group of resources.

Project layout and example

infra/
  main.tf
  variables.tf
  outputs.tf
  providers.tf
  envs/
    uat.tfvars
    prod.tfvars
terraform {
  required_version = ">= 1.6"
  required_providers {
    azurerm = {
      source  = "hashicorp/azurerm"
      version = "~> 3.100"
    }
  }
  backend "azurerm" {}   # values passed at init time
}

provider "azurerm" {
  features {}
  use_oidc = true
}
variable "env" {
  type = string
}

variable "location" {
  type    = string
  default = "centralindia"
}
resource "azurerm_resource_group" "rg" {
  name     = "rg-demo-${var.env}"
  location = var.location
  tags     = { env = var.env, managed_by = "terraform" }
}

resource "azurerm_container_registry" "acr" {
  name                = "acrdemo${var.env}001"   # globally unique, lowercase
  resource_group_name = azurerm_resource_group.rg.name
  location            = azurerm_resource_group.rg.location
  sku                 = "Basic"
}

resource "azurerm_log_analytics_workspace" "law" {
  name                = "law-demo-${var.env}"
  resource_group_name = azurerm_resource_group.rg.name
  location            = azurerm_resource_group.rg.location
  sku                 = "PerGB2018"
  retention_in_days   = 30
}
env = "uat"
The same code gives you UAT and Prod: only the .tfvars file and the state key change.

Remote state in Azure Storage

Create the state storage once, manually or with a separate bootstrap config:

az group create -n rg-tfstate -l centralindia
az storage account create -n sttfstate12345 -g rg-tfstate -l centralindia --sku Standard_LRS --min-tls-version TLS1_2
az storage container create --account-name sttfstate12345 -n tfstate --auth-mode login
terraform init \
  -backend-config="resource_group_name=rg-tfstate" \
  -backend-config="storage_account_name=sttfstate12345" \
  -backend-config="container_name=tfstate" \
  -backend-config="key=demo-uat.tfstate" \
  -backend-config="use_oidc=true"

The azurerm backend takes a blob lease for locking, so two runs cannot write state at once.

Passwordless auth: GitHub OIDC to Azure

No client secret is stored in GitHub. GitHub presents a short-lived token and Azure trusts it.

# 1. App registration + service principal
az ad app create --display-name gh-terraform
APP_ID=$(az ad app list --display-name gh-terraform --query "[0].appId" -o tsv)
az ad sp create --id $APP_ID

# 2. Federated credential for the main branch (repeat for pull_request / environments)
az ad app federated-credential create --id $APP_ID --parameters '{
  "name": "gh-main",
  "issuer": "https://token.actions.githubusercontent.com",
  "subject": "repo:YOUR_USER/YOUR_REPO:ref:refs/heads/main",
  "audiences": ["api://AzureADTokenExchange"]
}'
az ad app federated-credential create --id $APP_ID --parameters '{
  "name": "gh-pr",
  "issuer": "https://token.actions.githubusercontent.com",
  "subject": "repo:YOUR_USER/YOUR_REPO:pull_request",
  "audiences": ["api://AzureADTokenExchange"]
}'

# 3. Roles: Contributor on the subscription + data access to state storage
az role assignment create --assignee $APP_ID --role Contributor --scope /subscriptions/SUB_ID
az role assignment create --assignee $APP_ID --role "Storage Blob Data Contributor" \
  --scope $(az storage account show -n sttfstate12345 --query id -o tsv)

Add repository variables (or secrets): AZURE_CLIENT_ID, AZURE_TENANT_ID, AZURE_SUBSCRIPTION_ID. These are identifiers, not passwords.

If you use a GitHub environment: in the job, the OIDC subject becomes repo:USER/REPO:environment:NAME, so create a federated credential for it too.

GitHub Actions workflow

name: terraform
on:
  pull_request:
    paths: ["infra/**"]
  push:
    branches: [main]
    paths: ["infra/**"]

permissions:
  id-token: write      # OIDC
  contents: read
  pull-requests: write # to comment the plan

env:
  ARM_USE_OIDC: "true"
  ARM_CLIENT_ID: ${{ vars.AZURE_CLIENT_ID }}
  ARM_TENANT_ID: ${{ vars.AZURE_TENANT_ID }}
  ARM_SUBSCRIPTION_ID: ${{ vars.AZURE_SUBSCRIPTION_ID }}
  TF_IN_AUTOMATION: "true"

defaults:
  run:
    working-directory: infra

jobs:
  plan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: hashicorp/setup-terraform@v3
        with:
          terraform_version: 1.8.5
      - name: Init
        run: |
          terraform init \
            -backend-config="resource_group_name=rg-tfstate" \
            -backend-config="storage_account_name=sttfstate12345" \
            -backend-config="container_name=tfstate" \
            -backend-config="key=demo-uat.tfstate" \
            -backend-config="use_oidc=true"
      - run: terraform fmt -check -recursive
      - run: terraform validate
      - name: Plan
        run: terraform plan -input=false -var-file=envs/uat.tfvars -out=tfplan
      - name: Save plan
        uses: actions/upload-artifact@v4
        with:
          name: tfplan
          path: infra/tfplan

  apply:
    needs: plan
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    runs-on: ubuntu-latest
    environment: uat          # add required reviewers in repo Settings, Environments
    steps:
      - uses: actions/checkout@v4
      - uses: hashicorp/setup-terraform@v3
        with:
          terraform_version: 1.8.5
      - name: Init
        run: |
          terraform init \
            -backend-config="resource_group_name=rg-tfstate" \
            -backend-config="storage_account_name=sttfstate12345" \
            -backend-config="container_name=tfstate" \
            -backend-config="key=demo-uat.tfstate" \
            -backend-config="use_oidc=true"
      - uses: actions/download-artifact@v4
        with:
          name: tfplan
          path: infra
      - run: terraform apply -input=false tfplan
The job runs the exact plan that was reviewed. This avoids drift between "what I approved" and "what got applied".

Branching and approvals

  1. Open a PR that changes infra/. The plan job runs and shows what would change.
  2. A teammate reviews the plan output in the job log.
  3. Merge to main. The apply job waits for the uat environment approvers.
  4. Approve it and the infrastructure is provisioned.
  5. Repeat for prod with its own state key, tfvars and a stricter environment.

Best practices

  • Never commit *.tfstate, .terraform/ or secret tfvars. Add them to .gitignore.
  • Pin provider and Terraform versions, and commit .terraform.lock.hcl.
  • One state per environment; keep blast radius small.
  • Use terraform import or import blocks to adopt existing resources instead of recreating them.
  • Scan with tfsec/checkov in the pipeline.
  • Add budgets and tags for FinOps visibility on everything you provision.
