Ansible basics

Install and concepts

python3 -m pip install --user ansible
ansible --version
TermMeaning
Control nodeThe machine you run Ansible from. Needs Python. On Windows use WSL.
Managed nodeTarget server. Needs only SSH and Python.
InventoryList of hosts and groups.
ModuleA unit of work (apt, copy, service).
PlaybookYAML file with plays, each mapping hosts to tasks.
IdempotentRunning twice changes nothing the second time.

Inventory

[web]
web1 ansible_host=10.0.1.11
web2 ansible_host=10.0.1.12

[db]
db1 ansible_host=10.0.2.21

[all:vars]
ansible_user=ubuntu
ansible_ssh_private_key_file=~/.ssh/id_ed25519
ansible-inventory -i inventory.ini --list
ansible all -i inventory.ini -m ping

Ad-hoc commands

ansible web -i inventory.ini -m apt -a "name=nginx state=present update_cache=yes" --become
ansible web -i inventory.ini -m service -a "name=nginx state=restarted" --become
ansible all -i inventory.ini -a "df -h"
ansible db  -i inventory.ini -m copy -a "src=./my.cnf dest=/etc/mysql/my.cnf" --become

First playbook

---
- name: Configure web servers
  hosts: web
  become: true
  tasks:
    - name: Install nginx
      ansible.builtin.apt:
        name: nginx
        state: present
        update_cache: true

    - name: Ensure nginx is enabled and running
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true

    - name: Open firewall for HTTP
      community.general.ufw:
        rule: allow
        port: "80"
        proto: tcp
ansible-playbook -i inventory.ini site.yml --check --diff   # dry run
ansible-playbook -i inventory.ini site.yml                  # apply
ansible-playbook -i inventory.ini site.yml --limit web1 -v  # one host, verbose

Variables, templates, handlers

---
- name: Web with template and handler
  hosts: web
  become: true
  vars:
    app_port: 8080
    server_name: example.com
  tasks:
    - name: Render nginx site config
      ansible.builtin.template:
        src: templates/site.conf.j2
        dest: /etc/nginx/conf.d/site.conf
        mode: "0644"
      notify: Reload nginx

    - name: Only on Ubuntu
      ansible.builtin.debug:
        msg: "Ubuntu {{ ansible_distribution_version }}"
      when: ansible_distribution == "Ubuntu"

    - name: Create several users
      ansible.builtin.user:
        name: "{{ item }}"
        shell: /bin/bash
      loop: [deploy, backup]

  handlers:
    - name: Reload nginx
      ansible.builtin.service:
        name: nginx
        state: reloaded
server {
    listen 80;
    server_name {{ server_name }};
    location / {
        proxy_pass http://127.0.0.1:{{ app_port }};
    }
}
Handlers run once at the end of the play, and only if a task that notified them reported changed.

Roles

ansible-galaxy init roles/nginx

roles/nginx/
  tasks/main.yml        # the tasks
  handlers/main.yml
  templates/            # .j2 files
  defaults/main.yml     # lowest-priority variables
  vars/main.yml
- hosts: web
  become: true
  roles:
    - nginx

Vault for secrets

ansible-vault create group_vars/all/vault.yml
ansible-vault edit   group_vars/all/vault.yml
ansible-playbook site.yml --ask-vault-pass
ansible-playbook site.yml --vault-password-file ~/.vault_pass
Never commit the vault password file. In CI, pass it from a secret.

Best practices

  • Use fully qualified module names (ansible.builtin.copy).
  • Prefer modules over shell/command, so tasks stay idempotent.
  • Always run --check --diff before applying to production.
  • Keep one inventory per environment (inventories/uat, inventories/prod).
  • Lint with ansible-lint in CI.
