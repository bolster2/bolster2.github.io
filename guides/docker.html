Dockerfile instructions

InstructionPurpose
FROMBase image. Start of a stage.
WORKDIRSet working directory inside the image.
COPYCopy files from the build context.
RUNRun a command at build time and bake the result into a layer.
ENVSet an environment variable.
EXPOSEDocument the listening port (does not publish it).
USERSwitch to a non-root user.
CMDDefault command at container start (overridable).
ENTRYPOINTFixed executable; CMD supplies its default arguments.
HEALTHCHECKCommand Docker uses to judge container health.

The sample Node app

const http = require("http");
const port = process.env.PORT || 3000;

const server = http.createServer((req, res) => {
  if (req.url === "/health") {
    res.writeHead(200, { "Content-Type": "application/json" });
    return res.end(JSON.stringify({ status: "ok" }));
  }
  res.writeHead(200, { "Content-Type": "text/plain" });
  res.end(`Hello from Node ${process.version}\n`);
});

server.listen(port, () => console.log(`Listening on ${port}`));

// graceful shutdown so rolling updates do not drop requests
process.on("SIGTERM", () => server.close(() => process.exit(0)));

Simple Dockerfile

FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]
Copying package*.json before the rest of the code lets Docker reuse the cached dependency layer when only your source changes. This makes rebuilds much faster.

This sample has no dependencies, so it would have no lockfile. Run npm install once to generate package-lock.json before using npm ci, or use npm install --omit=dev instead.

Production multi-stage Dockerfile

# ---- build stage ----
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
# RUN npm run build        # uncomment for TypeScript / bundlers

# ---- runtime stage ----
FROM node:20-alpine
ENV NODE_ENV=production
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev && npm cache clean --force
COPY --from=build /app .
# COPY --from=build /app/dist ./dist   # when using a build step

# never run as root
USER node
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s \
  CMD wget -qO- http://localhost:3000/health || exit 1
CMD ["node", "server.js"]

Docker Compose

services:
  app:
    build: .
    ports:
      - "8080:3000"
    environment:
      PORT: 3000
      DB_HOST: db
    depends_on:
      db:
        condition: service_healthy
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: example     # use secrets in real environments
      POSTGRES_DB: app
    volumes:
      - dbdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 10

volumes:
  dbdata:
docker compose up -d --build
docker compose logs -f app
docker compose down            # add -v to also delete volumes

Push to ACR / Docker Hub

# Azure Container Registry
az acr login --name myacr
docker tag myapp:1.0 myacr.azurecr.io/myapp:1.0
docker push myacr.azurecr.io/myapp:1.0

# or build in the cloud without local Docker
az acr build -r myacr -t myapp:1.0 .

# Docker Hub
docker login
docker tag myapp:1.0 YOUR_USER/myapp:1.0
docker push YOUR_USER/myapp:1.0

Best practices

  • Pin base image versions (node:20-alpine), not latest.
  • Use multi-stage builds so compilers and dev dependencies stay out of the final image.
  • Run as a non-root user and use a .dockerignore.
  • One process per container; log to stdout/stderr.
  • Never bake secrets into images. Pass them at runtime.
  • Scan images: docker scout cves myapp:1.0 or Trivy (trivy image myapp:1.0).
